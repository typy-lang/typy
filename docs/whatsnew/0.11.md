# What's new in TyPy 0.11

TyPy 0.11.0 was released on 2026-11-22. This page summarises what it
changes for you as you write programs; the
[changelog](changelog.md#0110-2026-11-22) lists every change, with the
requirement and the decision record of each.

## Summary

- `object` as a type, narrowed by `isinstance`, class patterns and
  `type(x) is C`.
- `typing.cast`, checked when the program runs.
- Arithmetic on `bool`, as CPython does it.
- Nested functions, methods and lambdas with defaults, `*args` or
  `**kwargs` as values.
- Typing values and type aliases as values, such as `int | None` and
  `Pair.__value__`.
- `*` of any iterable in calls of function values, built-ins, methods and
  exception classes, and `**` of a dict in calls of `print`, protocol
  methods and exception classes.
- Nested functions with type parameters of their own.
- Every program of the benchmark suite built with `--release` runs faster
  than with CPython 3.15.

## `object` as a type

A variable, a parameter, an attribute, a result or an item of a
collection annotated `object` holds a value of any type. It compares,
prints and tests its truth as its value does, and `isinstance`, a class
pattern or `type(x) is C` narrows it before any other operation (TYP-23):

<!-- typy-expect: accepted -->
```python
items: list[object] = [1, "kiwi", None, 2.5]
for item in items:
    if isinstance(item, str):
        print(item.upper())
    else:
        print(item, item == 1)
```

`isinstance(x, int)` narrows to `int | bool`, since a `bool` stays a
`bool`. Narrowing to a collection, such as `isinstance(x, list)`, waits
for `typing.Any` in 0.13.

## `typing.cast`

`cast(T, value)` checks the value when the program runs. A value of `T`
passes, and any other raises `TypeError`, such as `cast to int found
str`, where CPython trusts the cast and goes on (TYP-24):

<!-- typy-expect: accepted -->
```python
from typing import cast

value: object = "kiwi"
name = cast(str, value)
print(name.title())
```

A cast to a collection of items, such as `list[int]`, is refused, since
the check would have to read every item.

## Arithmetic on `bool`

A `bool` beside a number is the `int` 0 or 1, as in CPython, and `&`,
`|` and `^` of two bools still give a `bool` (DAT-19):

<!-- typy-expect: accepted -->
```python
flags = [True, False, True]
print(sum(flags), True + 1, True / 2, -True, "ab" * True)
print(True & False, type(True | False).__name__)
```

`~` of a `bool` stays E0406: CPython 3.12 deprecates it, and Python 3.16
removes it.

## Functions as values

A nested function, a method or a `lambda` with defaults, `*args` or
`**kwargs` is a value where a `Callable` is expected that its parameters
take, as a function of a module is since 0.10 (FUN-19). The value is the
function itself to `is`, `==`, `hash` and `repr`:

<!-- typy-expect: accepted -->
```python
from collections.abc import Callable


def apply(function: Callable[[int, int], int], value: int) -> int:
    return function(value, 2)


def main() -> None:
    def add(value: int, *more: int) -> int:
        return value + sum(more)

    print(apply(add, 1))
    print(sorted([3, 1, 2], key=lambda value, by=10: by - value))


main()
```

## Typing values and type aliases

A name of `typing` or `collections.abc`, such a name or a built-in class
given type arguments, and a union written with `|` are values. A program
stores, passes, compares and writes them as CPython 3.15 writes them
(TYP-18):

<!-- typy-expect: accepted -->
```python
from typing import Optional

kinds = [list[int], int | None]
print(kinds, Optional[int] == int | None)
```

A type alias's `__value__` and `__type_params__` are values, and so is a
generic alias given type arguments, such as `Pair[int]`:

<!-- typy-expect: accepted -->
```python
type Pair[T] = tuple[T, T]

print(Pair.__value__, Pair.__type_params__)
numbers: Pair[int] = (2, 3)
print(numbers)
```

Writing a typing value that an older CPython from the program's floor
writes otherwise is E0202: `print(Optional[int])` needs the floor 3.14,
and `print(Pair[int])` the floor 3.15.

## Unpacking in calls

A call of a function value, a built-in, a method of a built-in type, a
function of `math` or `sys`, or an exception class takes `*` of any
iterable. When the program runs, it checks that the values are as many as
the call takes, and raises CPython's `TypeError` when they are not.
`print`, a method called through a protocol value and an exception class
take `**` of a dict held in a variable (EXP-22):

<!-- typy-expect: accepted -->
```python
from collections.abc import Callable


def add(left: int, right: int) -> int:
    return left + right


values = [3, 4]
function: Callable[[int, int], int] = add
print(function(*values), max(*values), range(*values))
options = {"sep": ", ", "end": ".\n"}
print(*values, **options)
```

`**` in a call of a function value is planned for 1.0 (EXP-21), and in a
call of a built-in other than `print` for 1.0 as well (EXP-24,
ADR-0099).

## Nested generic functions

A function nested in another may have type parameters of its own. Each
call runs the copy for its types, with the variables it captures
(FUN-18):

<!-- typy-expect: accepted -->
```python
def main() -> None:
    label = "seen"

    def tagged[T](value: T) -> tuple[str, T]:
        return (label, value)

    print(tagged(3), tagged("kiwi"))


main()
```

## Speed

Every program of the benchmark suite built with `--release` runs faster
than with CPython 3.15 (NFR-21); the
[benchmark report](../testing/benchmark-report.md) has the figures.
The work that got there:

- The methods of `str` and `bytes` read text of one byte a code point a
  run of bytes at a time, and slices of such text copy their bytes as a
  run.
- A `str` hashes and compares by its stored data and keeps its hash once
  it is first hashed, and every `str` of one character up to U+00FF is
  shared, as in CPython (ADR-0101).
- Debug and `--release` builds link a runtime optimised for speed.
  `--release-small` builds link the runtime optimised for size, installed
  in `lib/typy-small/`, so a hello world stays within its size budget
  (ADR-0100).

## Migrating from 0.10

- E0403 is retired. `object` and `typing.cast`, which it refused, are
  accepted, and `typing.Any` is E0201, planned for 0.13.
- A form a later release gives is now E0201, with the release in the
  message: `Literal`, `overload`, `Self`, `TypeGuard` and `TypeIs` 0.12;
  `typing.Any` and `TypedDict` with `Required`, `NotRequired` and
  `ReadOnly` 0.13; the modules `enum`, `abc`, `textwrap`, `base64`,
  `heapq`, `bisect`, `statistics`, `time`, `random`, `copy` and
  `string` 0.12; `from __future__ import annotations` and the builtins
  `divmod`, `bin`, `hex`, `oct`, `pow`, `format` and `bytearray` 0.12;
  `os` 1.0; and `doctest` a release after 1.0. They were E0202, E0206,
  E0403 or E0425. A script that reads `--error-format json` and matches
  these codes matches E0201 instead.
- A nested function or a method with `*args` or `**kwargs` read where no
  `Callable` is expected is E0203, with the help to annotate the
  variable; it was E0201. Such a function read as a value inside another
  nested function was accepted with a wrong type, and is now refused.
- An installation of TyPy needs `lib/typy-small/` beside `lib/typy/` for
  `--release-small` builds. The release archives hold both.

## Other changes

- A class method called through `super()` takes the class of the
  instance as `cls`, as in CPython; it took the base that defines it.
  Where the enclosing class or a class derived from it defines the class
  method again, the call is E0201, planned for 0.14.
- `enumerate`, `zip` and `reversed` read as a value with a keyword, such
  as `pairs = enumerate(items, start=1)`, are E0201, planned for after
  1.0, as they are without one.
- `type(value)` of a value whose type is `None` or a union, such as
  `None | int | str`, gives the type of the value it holds; the program
  stopped with "an object has an unknown type".
- `isinstance(None, Optional[int])` is true, as in CPython; it was false.
- `isinstance` takes a union written with `|`, such as
  `isinstance(x, int | None)`.
- From the Python floor 3.14, template strings are refused as planned
  for 0.13; from the floor 3.15, `[*row for row in rows]`, `frozendict`
  and `math.integer` are refused as planned for 0.12.
- A `str` or `bytes` takes 8 more bytes, for its hash. The pointer a C
  function gets for a `bytes` is the start of its data, as before.
- The [corpus report](../testing/corpus-report.md) gives the share of
  667 modules of typed Python written by others that TyPy builds unchanged
  and runs as CPython does, and what keeps the others out. The release
  workflow fails when the share falls.
