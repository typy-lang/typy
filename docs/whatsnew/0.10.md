# What's new in TyPy 0.10

TyPy 0.10.0 was released on 2026-11-21. This page summarises what it
changes for you as you write programs; the
[changelog](changelog.md#0100-2026-11-21) lists every change, with the
requirement and the decision record of each.

## Summary

- Decorators on functions, at the top of a module or nested in a
  function.
- Built-in functions, methods of built-in types, built-in types and
  functions with defaults or `*args` as values where a `Callable` is
  expected, such as `sorted(words, key=str.lower)`.
- Class methods, protocol methods and overridden methods read as values,
  bound as CPython binds them.
- `map` and `filter`, and `*` of a tuple written out in a call of a
  builtin.
- Classes derived from `typing.NamedTuple`.
- `Sequence`, `Mapping` and the other abstract collections as types.
- `isinstance`, `issubclass` and class patterns with a class held in a
  value, and `type[C]` that holds a class derived from `C`.
- Each release archive comes with a bill of materials and a signed
  attestation of how it was built.

## Decorators

A decorator is any expression that takes the function. The decorators
are evaluated from the top down and applied from the bottom up when the
`def` runs, and the name holds what the outermost returns, as in CPython
(FUN-06, ADR-0082):

<!-- typy-expect: accepted -->
```python
from collections.abc import Callable


def logged(function: Callable[[int], int]) -> Callable[[int], int]:
    def wrapper(value: int) -> int:
        result = function(value)
        print(f"{value} -> {result}")
        return result

    return wrapper


@logged
def double(value: int) -> int:
    return value * 2


print(double(double(3)))
```

A call through a decorated name passes its arguments by position, since
a `Callable` names no parameters. A decorator on a method is planned for
0.14 (FUN-15), and a class decorator other than `@dataclass` for 1.0
(CLS-38).

## Built-ins as values

Where a `Callable` is expected, a built-in function, a function of `math`
or `sys`, a method of a built-in type read through the type or through a
value, and a built-in type such as `int` are values. Each is written and
compared as CPython's is (FUN-08, FUN-14, ADR-0076, ADR-0077):

<!-- typy-expect: accepted -->
```python
import math
from collections.abc import Callable

words = ["pear", "Fig", "apple"]
print(sorted(words, key=len), sorted(words, key=str.lower))
print(max([-3.5, 2.0], key=math.fabs), list(map(int, ["4", "2"])))
measure: Callable[[str], int] = len
add: Callable[[str], None] = words.append
add("kiwi")
print(measure, measure("kiwi"), words)
```

With no `Callable` expected, a built-in other than `chr` and `ord` is
E0203, since its arguments may be of several types: annotate the
variable with the types you call it with. A function of the program with
defaults, `*args` or `**kwargs` fits a `Callable` of the arguments it
takes, and stays the same function to `is` and `==` (FUN-13, ADR-0080).

## Methods as values

A class method read as a value is bound to the class it is read through,
or to the instance's own class. A method read through a protocol value,
or through an instance whose subclass defines it again, is the method of
the object's own class, as CPython chooses it (FUN-09, ADR-0079):

<!-- typy-expect: accepted -->
```python
from typing import Protocol


class Shape(Protocol):
    def area(self) -> float: ...


class Square:
    def __init__(self, side: float) -> None:
        self.side = side

    def area(self) -> float:
        return self.side * self.side

    @classmethod
    def unit(cls) -> "Square":
        return cls(1.0)


make = Square.unit
shape: Shape = make()
area = shape.area
print(area(), area == shape.area)
```

## Named tuples

A class derived from `typing.NamedTuple` is a tuple of its fields with
names. It is built by position or by name, read by field name, an index,
a slice or unpacking, and printed, compared and hashed as that tuple.
Its body may hold methods, and `_fields`, `_asdict()` and `_replace()`
are given (CLS-27, ADR-0088):

<!-- typy-expect: accepted -->
```python
from typing import NamedTuple


class Point(NamedTuple):
    x: int
    y: int = 0

    def norm(self) -> int:
        return abs(self.x) + abs(self.y)


point = Point(3, y=-4)
x, y = point
print(point, point.norm(), point[0], x + y)
print(point._replace(y=1), point._asdict(), point == (3, -4))
```

## Abstract collections

`Sequence`, `MutableSequence`, `Mapping`, `MutableMapping`, `Set`,
`MutableSet`, `Collection`, `Container`, `Reversible`, `KeysView`,
`ValuesView` and `ItemsView` hold the built-in collections CPython
registers with them, such as a list, a tuple, `bytes` or a `range` for a
`Sequence[int]`. One that only reads its items takes a collection of a
derived class's instances, such as a `list[Square]` for a
`Sequence[Shape]` (LIB-20, ADR-0086):

<!-- typy-expect: accepted -->
```python
from collections.abc import Mapping, Sequence


class Shape:
    def area(self) -> float:
        return 0.0


class Square(Shape):
    def area(self) -> float:
        return 4.0


def total(shapes: Sequence[Shape]) -> float:
    return sum((shape.area() for shape in shapes), 0.0)


def describe(sizes: Mapping[str, int]) -> list[str]:
    return [f"{name}={size}" for name, size in sizes.items()]


squares = [Square(), Square()]
print(total(squares), total((Shape(),)), describe({"a": 1}))
print(list(reversed(range(3))), isinstance(squares, Sequence))
```

## `map`, `filter` and unpacking in calls

`map` and `filter` make lazy iterators that take a function of the
program, a `lambda` or a built-in such as `int`, and are written as
`<map object at 0x...>` (LIB-23, ADR-0089). A call of a builtin, a
function value, a protocol method or an exception class takes `*` of a
tuple display or of a variable holding a fixed tuple, and `**` of a dict
display with `str` keys (EXP-19):

<!-- typy-expect: accepted -->
```python
values = [3, 8, 1]
evens = filter(lambda value: value % 2 == 0, values)
doubled = map(lambda value: value * 2, values)
print(list(evens), list(doubled), list(map(max, [2, 3], [3, 1])))
point = (3, 4)
print(max(*point), "-".join(["a", *"bc"]))
print(*point, **{"sep": ", "})
```

## Classes held in values

`isinstance`, `issubclass` and class patterns take a class held in a
variable or a parameter, or a tuple of them, tested when the program
runs. A `type[Shape]` holds `Shape` or a class derived from it
(CLS-18, CLS-19, ADR-0084):

<!-- typy-expect: accepted -->
```python
class Shape:
    pass


class Circle(Shape):
    pass


def kind_of(shape: Shape, kinds: tuple[type[Shape], ...]) -> str:
    for kind in kinds:
        if isinstance(shape, kind):
            return kind.__name__
    return "unknown"


circle: Shape = Circle()
print(kind_of(circle, (Circle, Shape)), issubclass(Circle, Shape))
match circle:
    case Circle():
        print("a circle")
```

## Release archives

Each release archive holds `sbom.cdx.json`, a CycloneDX bill of materials
of its files and of the crates and libraries the compiler holds (NFR-25).
Each archive is attested with its build provenance, signed through
Sigstore, so you can check where it was built (NFR-26):

```sh
gh attestation verify typy-0.10.0-x86_64-unknown-linux-gnu.tar.gz \
    --repo typy-lang/typy
```

## Migrating from 0.9

- `type(x)` of an instance whose class has subclasses, such as a
  `Circle` held as a `Shape`, is a class known only when the program
  runs. Calling it, or reading a class variable or a class method
  through it, is E0201, planned for 0.14 (CLS-39): 0.9 used the static
  class, where CPython uses the instance's own. The same holds for a
  `type[Shape]` variable or parameter when `Shape` has subclasses. Call
  the class by its name, or pass a function that makes the object.
- A property read through its class as a value, such as `getter =
  Box.v`, is E0201, planned for 1.0 (FUN-17): 0.9 gave the getter, where
  CPython gives a `property` object. Read it through an instance.
- `x += y` where the class of `x` has an `__iadd__` whose parameter does
  not take `y` is E0404, since CPython calls `__iadd__` whatever `y` is;
  0.9 called `__add__`.
- An override that takes a parameter by keyword only, or by position
  only, where its base method takes it by position or by keyword is
  E0404, since CPython refuses a call through the base with `TypeError`.
- An exception class that defines `__eq__` or `__ne__` is E0201, planned
  for 1.0 (EXC-20), since TyPy does not call it yet; `==` and `!=` of two
  exceptions compare them by identity, as CPython's default does.
- `typing` names and type aliases as values, nested functions with type
  parameters of their own, nested functions and methods with defaults,
  `*args` or `**kwargs` as values, and `*` of a list in a call of a
  builtin are planned for 0.11 (TYP-18, FUN-18, FUN-19, EXP-22). The
  generics and `ctypes` features planned for 1.0 are planned for 0.13,
  and the class rules for 0.14.

## Other changes

- A fixed tuple passed where a union with a `tuple[T, ...]` member is
  expected, a generic function whose parameters name a type parameter
  inside a `Callable` or a `Generator`, and a fixed tuple, a collection
  or an iterator passed where a union of iterables is expected now
  compile, as in CPython.
- A library called on a thread its C host created with a small stack
  raises `RecursionError` for a recursion too deep for that stack, where
  the process ended with a segmentation fault (FFI-15).
- Messages that refuse a builtin's keyword argument use CPython's text,
  and messages for names a module does not give list the names it does
  give.
